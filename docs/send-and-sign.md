# Отправка и подписание документов

Практическая инструкция по формированию, отправке и подписанию ЭПД
(ЭТрН / ЭЗЗ / ЭПЛ) через библиотеку `saby-tms-client`.

> Низкоуровневое описание JSON-RPC методов — в [`how-to.md`](../how-to.md).
> Здесь — типобезопасный клиент `SabyTmsClient` и готовые рецепты кода.

---

## 1. Модель работы

Отправка документа — это **два независимых этапа**:

1. **Запись** (`ЗаписатьДокумент` для Т1, `ЗаписатьВложение` для Т2+).
   Создаёт карточку документа/титула, но ещё **не подписывает** и **не отправляет**.
2. **Подписание** (`ПодготовитьДействие` → `ВыполнитьДействие`).
   Подписывает документ КЭП и отправляет его в ГИС ЭПД.

Между записью и подписанием можно выполнить произвольные действия
(проверить данные, прочитать карточку и т.п.).

| Метод | Назначение | Результат |
|-------|-----------|-----------|
| `login(credentials)` | Авторизация + выбор организации-инициатора | id сессии (хранится внутри) |
| `toAttachment(Document*(data, meta))` | Сборка готового тела документа (файл + `Тип`/`Регламент`) | тело `Документ` |
| `writeDocument(body, opts)` | Создание **нового** документа (Т1) | карточка документа |
| `writeAttachment(parent, body, opts)` | Добавление **титула Т2+** к существующему документу | карточка документа |
| `prepareAction(card, opts)` | Подготовка подписи (получение хеша) | этап `Этап[0]` |
| `executeAction(card, opts)` | Подписание и отправка | результат выполнения |
| `listChanges(card?, opts)` | Статусы / поиск входящих документов | список изменений |
| `readDocument(card, extra?)` | Чтение полной карточки документа | карточка |

## 2. Предварительные условия

```ts
import {
    SabyEnv,
    SabyTmsClient,
    organization,
} from "saby-tms-client";

const client = new SabyTmsClient(SabyEnv.Test); // Test или Prod
```

Авторизация — **обязательно с организацией** (она подставляется в
`НашаОрганизация` при записи документа):

```ts
await client.login({
    login: "@demo41709796",
    password: "@demo41709796",
    organization: organization({ inn: "2145492416", kpp: "214501001" }),
});
```

Форма организации (`СвЮЛ` / `СвФЛ` / `СвИП`) определяется автоматически по
длине ИНН — 10 цифр это юрлицо, 12 — физлицо/ИП.

## 3. Два способа подписания

### 3.1. Серверный ключ (demo / тест)

Сервер подписывает документ своим ключом — **клиентская подпись не нужна**.
Используется в demo-окружении.

```ts
const prepared = await client.prepareAction(card, {
    action: EplAction.Send,
    certificateThumbprint: THUMBPRINT, // отпечаток КЭП (серверный)
    comment: "Отправка документа",
});

await client.executeAction(card, {
    stage: stageOf(prepared),
    keyType: "Серверный",
});
```

### 3.2. Клиентский ключ (КЭП / КриптоПро)

Классическая схема: клиент получает хеш, подписывает его внешней КЭП,
затем отправляет подписанный этап.

```ts
const prepared = await client.prepareAction(card, {
    action: EplAction.Send,
    certificateThumbprint: "961A25F64E749882994B491757E3F88C95DD0A04",
});

// 1. Извлечь хеш из prepared (Этап[0]).
// 2. Подписать хеш внешним средством (КриптоПро и т.п.) → подписанные данные.
// 3. Передать подписанный этап на выполнение.
await client.executeAction(card, {
    stage: signedStage,
    keyType: "Клиентский",
});
```

Вспомогательная функция извлечения этапа:

```ts
function stageOf(prepared: unknown): Record<string, unknown> {
    const stages = (prepared as Record<string, unknown>)["Этап"] as Record<string, unknown>[];
    const stage = stages[0];
    if (!stage) throw new Error("ПодготовитьДействие не вернул Этап[0]");
    return stage;
}
```

## 4. Полный цикл создания документа (Т1)

```ts
import {
    SabyEnv, SabyTmsClient, organization,
    EplAction, Document1110380, toAttachment,
} from "saby-tms-client";

const client = new SabyTmsClient(SabyEnv.Test);
try {
    // 0. Авторизация.
    await client.login({
        login: "@demo41709796",
        password: "@demo41709796",
        organization: organization({ inn: "2145492416", kpp: "214501001" }),
    });

    // 1. Фабрика собирает готовое вложение из конструктора:
    //    имя файла + base64 XML + Тип/Подтип. Мапперы не нужны.
    const attachment = toAttachment(Document1110380(waybillData));

    // 2. Запись нового документа (Т1).
    const card = await client.writeDocument(attachment);

    // 3. Подготовка подписи.
    const prepared = await client.prepareAction(card, {
        action: EplAction.Send,              // "Отправить"
        certificateThumbprint: THUMBPRINT,
        comment: "Отправка Т1",
    });

    // 4. Подписание и отправка (серверный ключ в demo).
    await client.executeAction(card, {
        stage: stageOf(prepared),
        keyType: "Серверный",
    });

    // 5. Проверка статуса (опционально).
    const read = await client.readDocument(card, "Расширение,ЭПД");
    console.log("Состояние:", read.Состояние);
} finally {
    client.dispose();
}
```

## 5. Добавление титула (Т2+)

Титул Т2+ прикрепляется к **существующему** документу через `writeAttachment`.

```ts
import {
    EplAction, Document1110381, toAttachment,
} from "saby-tms-client";

// parent — карточка документа (входящего, либо созданного ранее Т1).
const attachment = toAttachment(Document1110381(medicalExamData));

await client.writeAttachment(parent, attachment);

const prepared = await client.prepareAction(parent, {
    action: EplAction.Admitted,   // "Допущен" (медосмотр)
    certificateThumbprint: THUMBPRINT,
    comment: "Медосмотр пройден",
});

await client.executeAction(parent, {
    stage: stageOf(prepared),
    keyType: "Серверный",
});
```

**Поиск входящего документа** (для работы контрагента):

```ts
const incoming = await client.listChanges(undefined, {
    documentType: DocumentType.ETRN, // или EZZ / EPL
    direction: "Входящий",
});
```

## 6. Справочник документов

> Все конструкторы ниже подаются в фабрику `toAttachment(...)` — она сама
> выводит `Тип`/`Регламент` из КНД.

### 6.1. ЭТрН — Транспортная накладная (`ConsignmentNote`)

| Титул | Подтип | Конструктор | Действие |
|-------|--------|-------------|----------|
| Т1 | 1110339 | `Document111339` | `EtRnAction.Loaded` («Погружен») |
| Т2 | 1110340 | `Document1110340` | `EtRnAction.Accepted` («Принят») |
| Т3 | 1110341 | `Document1110341` | `EtRnAction.Received` («Получен») |

### 6.2. ЭЗЗ — Заказ/заявка на перевозку (`TransportOrder`)

| Титул | Подтип | Конструктор | Действие |
|-------|--------|-------------|----------|
| Т1 | 1110361 | `Document1110361` | `EzzAction.Send` («Отправить») |
| Т2 | 1110362 | `Document1110362` | `EzzAction.Approve` («Утвердить») / `EzzAction.Reject` («Отклонить») |

### 6.3. ЭПЛ — Путевой лист (`Waybill`)

| Титул | Подтип | Конструктор | Действие |
|-------|--------|-------------|----------|
| Т1 | 1110380 | `Document1110380` | `EplAction.Send` («Отправить») |
| Т2 | 1110381 | `Document1110381` | `EplAction.Admitted` («Допущен», медосмотр) |
| Т3 | 1110382 | `Document1110382` | `EplAction.Admitted` («Допущен», техосмотр) |
| Т4 | 1110383 | `Document1110383` | `EplAction.Released` («Выпущен», выезд) |
| Т5 | 1110384 | `Document1110384` | `EplAction.Accepted` («Принят», заезд) |

## 7. Важные правила и подводные камни

1. **Вложение собирается фабрикой `toAttachment`.**
   Передавайте в `writeDocument`/`writeAttachment` результат
   `toAttachment(Document*(data, meta))` — он уже содержит имя файла,
   base64-XML и `Тип`/`Регламент`. Никаких мапперов или `substitution` не требуется:

   ```ts
   const card = await client.writeDocument(toAttachment(Document1110380(data)));
   ```

2. **`ЗаписатьДокумент` — только для Т1** (новый документ, инициатор).
   Все последующие титулы прикрепляются через `ЗаписатьВложение` к
   `Идентификатору` существующего документа.

3. **Порядок: конструктор → фабрика.**
   `Document*` возвращает XML-узел `<Файл>` (стандарт ФНС), а `toAttachment`
   сериализует его в windows-1251/base64 и добавляет `Тип`/`Регламент`.

4. **ЭТрН, ЭЗЗ и ЭПЛ собираются одинаково** — `toAttachment` сам выводит
   `Тип` из КНД (`SUBTYPE_TO_DOCUMENT_TYPE`), поэтому отдельной логики для
   ЭТрН Т2/Т3 (1110340/1110341) не требуется.

5. **Контрагентские титулы требуют второго аккаунта.**
   Родительский документ должен быть **входящим** (`Направление="Входящий"`),
   поэтому для полного цикла Т2+ нужен второй demo-аккаунт (контрагент).

6. **Авторизация задаёт организацию** (`organization({...})`) — она
   автоматически подставляется в `НашаОрганизация` при `ЗаписатьДокумент`.

7. **Сертификат КЭП** указывается в `prepareAction` отпечатком (SHA-1, 40 hex),
   либо реквизитами `ФИО` / `Должность` / `ИНН`, либо не указывается вовсе
   (сервер подставит доступный сам). В demo-окружении используется серверный
   ключ (`keyType: "Серверный"`), в боевом — клиентская КЭП (`keyType: "Клиентский"`).

8. **Отключение клиента** — после завершения работы вызывайте `client.dispose()`
   (освобождает сессию и отклоняет ожидающие запросы).

## 8. `certificateThumbprint` — отпечаток сертификата: что это и где взять

### Простыми словами

Электронная подпись — это как **паспорт**. У паспорта есть номер и серия.
У электронной подписи тоже есть свой «номер» — он называется
**отпечаток сертификата** (по-английски *thumbprint*).

- **Отпечаток** — это короткий уникальный код из 40 букв и цифр, например
  `7C4F04C13E4C852043724D0001402457297CD322`.
- Это **не секрет**. Его можно спокойно показывать и передавать — это как
  сказать номер паспорта, а не сам паспорт.
- Зачем он нужен? Чтобы сервер понял, **какой именно** подписью подписывать
  документ. У одного человека может быть несколько подписей (личная, от имени
  фирмы) — отпечаток говорит серверу, какую взять.

### Что это в коде

Поле передаётся в `prepareAction`:

```ts
await client.prepareAction(card, {
    action: EplAction.Send,
    certificateThumbprint: "7C4F04C13E4C852043724D0001402457297CD322",
});
```

Под капотом оно уходит на сервер как `Этап.Действие.Сертификат.Отпечаток`.

> Важно: `Сертификат` можно **не передавать**. Если его опустить, сервер сам
> подставит доступный сертификат и вернёт его отпечаток в ответе (см.
> «Вариант В» ниже).

### Чем ещё можно указать сертификат

Помимо отпечатка, в объекте `Сертификат` сервер принимает и другие реквизиты
(любую их комбинацию):

| Поле | Что передавать | Пример |
|------|----------------|--------|
| `Отпечаток` | SHA-1 (40 hex) | `7C4F04C13E4C852043724D0001402457297CD322` |
| `ФИО` | Фамилия Имя Отчество | `"Главный Сергей Александрович"` |
| `Должность` | Название должности | `"Генеральный директор"` |
| `ИНН` | ИНН владельца | `"763661018497"` |

В клиенте это задаётся через поле `certificate` (а `certificateThumbprint` —
это просто короткая запись для `certificate: { "Отпечаток": "..." }`):

```ts
// По отпечатку (короткая запись).
await client.prepareAction(card, {
    action: EplAction.Send,
    certificateThumbprint: "7C4F04C13E4C852043724D0001402457297CD322",
});

// По ФИО / должности / ИНН — любой комбинации полей.
await client.prepareAction(card, {
    action: EplAction.Send,
    certificate: {
        "ФИО": "Главный Сергей Александрович",
        "Должность": "Генеральный директор",
        "ИНН": "763661018497",
    },
});

// Вообще без сертификата — сервер выберет доступный сам.
await client.prepareAction(card, { action: EplAction.Send });
```

### Полный пример без отпечатка

Ниже — тот же цикл отправки, что и в разделе 4, но **без единого упоминания
отпечатка**: сертификат подписанта либо указан реквизитами, либо не указан
вовсе (сервер сам подставит доступный).

```ts
import {
    SabyEnv, SabyTmsClient, organization,
    EplAction, Document1110380, toAttachment,
} from "saby-tms-client";

const client = new SabyTmsClient(SabyEnv.Test);
try {
    await client.login({
        login: "@demo41709796",
        password: "@demo41709796",
        organization: organization({ inn: "2145492416", kpp: "214501001" }),
    });

    const card = await client.writeDocument(toAttachment(Document1110380(waybillData)));

    // Подписываем БЕЗ отпечатка.
    //
    // Способ 1: по ФИО / должности / ИНН (любая комбинация).
    const prepared = await client.prepareAction(card, {
        action: EplAction.Send,
        certificate: {
            "ФИО": "Главный Сергей Александрович",
            "Должность": "Генеральный директор",
            "ИНН": "763661018497",
        },
    });

    // Способ 2 (альтернатива): вообще без «Сертификат».
    // Сервер сам подставит доступный сертификат и вернёт его в ответе.
    // const prepared = await client.prepareAction(card, { action: EplAction.Send });

    // Подписание и отправка (серверный ключ в demo).
    await client.executeAction(card, {
        stage: stageOf(prepared),
        keyType: "Серверный",
    });
} finally {
    client.dispose();
}
```

### Где взять отпечаток

**Вариант А — ваша настоящая подпись (КЭП).** Отпечаток смотрится в программе,
где хранится подпись:

1. Откройте **КриптоПро CSP** (или ViPNet CSP — смотря что установлено).
2. Перейдите в раздел **«Сертификаты»**.
3. Найдите нужный сертификат и откройте его **свойства**.
4. Найдите поле **«Отпечаток SHA-1»** — это и есть нужный код.

> Частая ошибка: SHA-1 состоит из 40 символов. Если программа показывает
> «SHA-256» (64 символа) — это другой отпечаток, для `certificateThumbprint`
> нужен именно **SHA-1**.

**Вариант Б — отпечаток другого контрагента.** Если документ подписывает не
вы, а ваш партнёр, он присылает вам свой сертификат (файл `.cer`) или просто
отпечаток. Достаточно отпечатка — сам сертификат для передачи не обязателен.

**Вариант В — узнать через API (проверено на demo).** Сервер сам возвращает
отпечаток доступного сертификата в ответе на `ПодготовитьДействие`, даже если
`Сертификат.Отпечаток` **не передавать**. Достаточно вызвать метод без
сертификата и прочитать `Этап[0].Действие[0].Сертификат[0].Отпечаток`:

```ts
const prepared = await client.request("СБИС.ПодготовитьДействие", {
    "Документ": {
        "Идентификатор": card.Идентификатор,
        "Этап": { "Действие": { "Название": "Отправить" } }, // без «Сертификат»
    },
});

const action = prepared["Этап"][0]["Действие"][0];
const thumbprint = action["Сертификат"][0]["Отпечаток"];
// → "7C4F04C13E4C852043724D0001402457297CD322" на demo-аккаунте
```

Замечание: на demo сервер подставляет **единственный** доступный (серверный)
сертификат. Если у аккаунта несколько сертификатов — поведение может
отличаться, но на demo это рабочий способ узнать отпечаток без КриптоПро.

## 9. Подписание через Госключ (`client.sign.goskey`)

### Что такое Госключ

**Госключ** — это способ подписывать документы **с телефона**, без флешки
(токена) и без установки КриптоПро. Подпись хранится в защищённом «облаке»
у оператора, а вы подтверждаете подпись в мобильном приложении «Госключ» —
примерно как подтверждаете покупку в банковском приложении.

### Когда какой способ подписания использовать

| Способ | Когда использовать | Код |
|--------|--------------------|-----|
| **Серверный ключ** | Демо/тест; подпись хранится у оператора, ничего подтверждать не надо | `keyType: "Серверный"` |
| **Госключ** | У пользователя нет токена, но есть телефон с приложением «Госключ» | `client.sign.goskey.*` |
| **Клиентская КЭП** | У пользователя есть токен/КриптоПро, он подписывает сам | `keyType: "Клиентский"` |

Госключ — это «золотая середина»: подпись настоящая (КЭП), но хранится не у
пользователя на флешке, а в облаке, а пользователь просто подтверждает операцию
в телефоне.

### Виды подписи (`GoskeySignatureKind`)

```ts
GoskeySignatureKind.Nep        // НЭП — неквалифицированная (упрощённая)
GoskeySignatureKind.Kep        // КЭП — квалифицированная физлица
GoskeySignatureKind.KepLegal   // КЭПЮЛ — от имени юридического лица
GoskeySignatureKind.KepOfficial // КЭПДЛ — должностного лица
```

Для отправки ЭПД в ГИС ЭПД обычно используется **КЭП** или **КЭПЮЛ**.
Для `КЭПЮЛ` дополнительно передаются реквизиты организации:

```ts
ogrn: "…",            // ОГРН организации
ogrnip: "…",          // или ОГРНИП для ИП
headSnils: "…",       // СНИЛС руководителя
```

### Пошаговый порядок

```ts
import { GoskeySignatureKind } from "saby-tms-client";

// 1. У вас уже есть карточка документа (из writeDocument / readDocument).
const card = await client.writeDocument(attachment, { substitution });

// 2. Создаём операцию подписания. Госключ формирует «отсоединённую подпись».
const op = await client.sign.goskey.createOperation({
    signatureKind: GoskeySignatureKind.Kep,
    card, // карточка с вложениями, которые надо подписать
});

// 3. Теперь пользователь ОТКРЫВАЕТ приложение «Госключ» и подтверждает
//    подпись (нажимает «Подписать»). Это делает сам человек, а не код.

// 4. Опрашиваем статус, пока подпись не будет готова.
let result = await client.sign.goskey.getStatus(op.operationId);
while (result.operationStatus !== "Received") {
    await new Promise((r) => setTimeout(r, 1000));
    result = await client.sign.goskey.getStatus(op.operationId);
}

// 5. Подписанные данные лежат в result.files[].result (base64).
//    Их можно передать дальше (например, в executeAction).
const signedData = result.files?.[0]?.result;
```

### Важные замечания

1. **Перед первым использованием** пользователь должен привязать Госключ к
   своему аккаунту. Узнать, какие внешние провайдеры доступны и привязаны,
   можно так:

   ```ts
   const providers = await client.sign.goskey.getProviders();        // доступные
   const linked    = await client.sign.goskey.getLinkedProviders();  // привязанные
   ```

2. **`getStatus` нужно вызывать в цикле** — подпись выполняется не мгновенно:
   человек должен успеть подтвердить её в телефоне.

3. **Точные значения статуса завершения** (`"Received"` и др.) сверяйте с
   актуальной документацией оператора — в разных версиях API они могут
   называться по-разному. Главный признак готовности — заполненное поле
   `files[].result` и время `operationCompleted`.

4. **Требуется привязка учётной записи Госуслуг.** Без неё `createOperation`
   сразу возвращает ошибку (проверено на demo):

   ```json
   {
     "Operation": "createDetachedSign",
     "OperationStatus": "Error",
     "OperationError": "Пользователю не привязана учетная запись Госуслуг"
   }
   ```

   То есть перед использованием Госключа пользователь должен привязать свой
   аккаунт к Госуслугам.

5. **Госключ НЕ заменяет `ПодготовитьДействие`/`ВыполнитьДействие`** и **не
   возвращает** отпечаток сертификата. Это отдельный механизм
   (`sabyCryptoOperation.*`), который формирует «отсоединённую подпись» файла.
   Отпечаток (`certificateThumbprint`) для документооборота берётся только
   способами из раздела 8, а не из Госключа.

### Итоговая «шпаргалка для новичка»

1. **Создали документ** → получили карточку.
2. **Решили, чем подписывать**: телефон → Госключ; токен → клиентская КЭП.
3. **Сказали серверу, какой подписью подписывать** → передали
   `certificateThumbprint` (отпечаток — «номер паспорта» подписи).
4. **Подписали**: сервер сам (демо), или подтвердили в Госключе, или подписали
   токеном.
5. **Отправили** → `executeAction` → документ ушёл в ГИС ЭПД.
