# XML поручения экспедитору

Библиотечные конструкторы формата 5.01, часть 958:

| Конструктор       | Содержание                | XSD                                  |
| ----------------- | ------------------------- | ------------------------------------ |
| `Document1110486` | Информация клиента        | `ON_POREXPKLT_1_958_05_05_01_01.xsd` |
| `Document1110487` | Согласование экспедитором | `ON_POREXPEXP_1_958_06_05_01_01.xsd` |
| `Document1110488` | Отзыв клиентом            | `ON_POREXPOTZ_1_958_07_05_01_01.xsd` |

Основание: [приказ ФНС от 28.04.2026 № ЕД-1-26/277@, приложение № 1](https://www.nalog.gov.ru/rn77/about_fts/docs/16627946/).
Исходные XSD закреплены в `schemas/exp/`, их SHA-256 записаны в `src/docs/exp/validation/schemas.generated.ts`.
Это копии схем из репозитория, а не автоматически обновляемая нормативная база.

## Использование

```ts
import {
    Document1110486,
    toXml,
    encodeWindows1251,
    type TDocument1110486,
} from "saby-tms-client";

function createClientFile(data: TDocument1110486) {
    const node = Document1110486(data, { programTag: "MyApp 1.0" });
    return {
        name: `${node.Файл.ИдФайл}.xml`,
        bytes: encodeWindows1251(toXml(node)),
    };
}
```

Типы и перечисления доступны также через пространства имён `EXP1110486`, `EXP1110487`, `EXP1110488`.
Полные синтетические примеры находятся в `e2e/fixtures/exp-{client,forwarder,withdrawal}.ts`.
Даты `Date` форматируются в локальной временной зоне процесса; диапазоны времени с UTC-смещением передаются явно.
Имя сохраняемого файла без расширения должно совпадать с `ИдФайл`.

Т2 и Т3 требуют идентификатор, дату/время и фактическую подпись исходного файла клиента (`clientFileId`).
УИД поручения и реестровые сведения экспедитора передаются вызывающей стороной. Конструкторы их не выдумывают.
Отзыв — отдельный титул, который формируется при соответствующем событии.

## Полнота и проверки

Т1 поддерживает все ветви сторон (ЮЛ, ИП, ФЛ, иностранное лицо), адресов (РФ, ГАР, иностранный),
партий и грузов, опасных свойств, учёта в ГИС, контейнеров, стоимости, страхования,
услуг, документов и их составителей, исправлений, информационных полей и полномочий подписанта.
Т2 поддерживает услуги, привлечённого исполнителя, оплату/НДС, маршруты/ТС/водителей, исправления и подпись.
Т3 поддерживает отзыв, прекращение исполнения, расходы, возврат груза, контакты/адрес, исправление и подпись.

Перед возвратом XML-узла каждый конструктор проверяет обязательные элементы и атрибуты,
`sequence`/`choice`, кратность, перечисления, длины, шаблоны и числовые ограничения своей XSD.
Ошибки содержат путь поля, без вывода его значения. Проверяются XML 1.0 и возможность
сохранения текста в Windows-1251 без потерь. Заглушки для обязательных полей не подставляются.
Проверки условной обязательности находятся в форматтерах соответствующих структур.

В тестах каждое поле каждого сложного типа трёх XSD должно быть достижимо через публичные
конструкторы. 38 вариантов документов независимо проверяются libxml2 по исходным XSD и всем
применимым встроенным Schematron-условиям (28 / 19 / 7 правил, включая совпадение имени файла).
Негативные тесты сопоставляют отказы библиотечного валидатора с libxml2.
Особенность Т2 сохранена: количество зданий ГАР не ограничено; в Т1/Т3 максимум три.

Встроенный валидатор предназначен только для закреплённых трёх схем, не для произвольного XSD.
XSD и Schematron подтверждают структуру и условия формата; криптографическая проверка ЭП,
присвоение УИД, подписание и передача оператору/ГИС ЭПД не выполняются этими конструкторами.
Подключение к бизнес-логике приложения в это изменение не входит.

## Проверка и обновление

Из каталога библиотеки (для независимых проверок нужен Python 3 с `lxml`):

```sh
python3 scripts/generate-exp-schema.py --check
pnpm exec vitest run e2e/exp-client.test.ts e2e/exp-forwarder.test.ts e2e/exp-withdrawal.test.ts e2e/exp-xsd.test.ts
pnpm build
```

При обновлении исходных XSD выполнить `python3 scripts/generate-exp-schema.py`, сверить изменения
формата и прогнать проверки. Генерация выполняется только при разработке: готовая библиотека
не требует Python, файлов XSD или внешних процессов для формирования XML.
